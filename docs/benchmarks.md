## How to read these numbers

* **Everything here is simulated.** `SimHuman` is a model operator: saccadic gaze with
  fixational jitter + a spatially varying webcam calibration bias (0.9° / 1.5° / 2.5° RMS for
  optimistic / typical / pessimistic) + drift + head→gaze leakage; intermittent minimum-jerk
  corrective submovements (Meyer et al. 1988) with ~200–350 ms visual-motor delay; gain adaptation;
  it only clicks once the cursor it *sees* has settled inside the inner 60% of the target.
  Webgrid score = `max(log2(N²−1) · NTPM / 60, 0)` exactly like neuralink.com/webgrid.
* `mouseLike` is the same simulated human driving a near-perfect pointer — a *sanity ceiling for the
  simulator*, not a measurement of a real mouse (Neuralink has publicly cited roughly 10 BPS for able-bodied
  mouse users and high-single-digit BPS for its BCI participants — check neuralink.com/webgrid for current figures).
* Gaze alone is limited by the uncorrected webcam calibration bias (~60–75 pt at "typical"), which is
  larger than 30 pt cells. Since iteration 2 the simulated operator does *compensatory gazing*: it learns
  the offset between where it looks and where the cursor lands (from the delayed visual feedback) and aims
  its saccades at `target − learnedOffset`. Before this fix the operator fed the instantaneous error back with
  a gain, which oscillated through the ~250 ms visual delay, so gaze-only scored 0 on every grid.
  `gazeEKF` additionally runs the EKF in *gaze-only mode* when no head/hand correction channel is
  enabled/active: the bias state is a Schmidt-Kalman "consider" state (not updated from gaze — it is
  unobservable), its process noise is frozen, and the position process noise is raised so the cursor
  follows deliberate compensatory gaze. Gaze-only is usable on coarse grids (6×6–15×15) but still ~0 at
  30×30; head (AirPods) / hand fine correction is what removes the bias online and gives 5+ BPS.
* The tuner (`gazefuse-bench tune`) optimises the simulated score; real-world tuning needs real
  recordings (`replay`). Expect live numbers to be lower until the head/hand gains are tuned to you.

## Iteration 2 (appearance gaze, pupil refinement, jaw latency, adaptive pinch)

All numbers below come from the unit tests / benchmarks in this repo (synthetic data unless stated).

**Jaw clench (AirPods), 150 s mixed synthetic stream** (`MotionJawClenchTests`):

| | precision | recall | F1 | mean latency | p90 latency | 8-seed mean F1 |
|---|---:|---:|---:|---:|---:|---:|
| classic (commit after burst release) | 0.952 | 0.870 | 0.909 | 0.440 s | 0.552 s | 0.905 |
| **early commit** (default) | 0.952 | 0.870 | 0.909 | **0.120 s** | **0.251 s** | 0.905 |

Early commit fires during the burst once it has lasted 60 ms at ≥1.25× threshold, *only* if the preceding 0.6 s
was quiet and the head was still (|ω| ≤ 0.08 rad/s before and during). Without the head-still gate F1 fell to 0.870
(head-turn/walking false positives). Nuisance false positives unchanged (chewing 10.91/min — as before — others 0).
Disabled automatically when double-clench is enabled.

**Adaptive pinch thresholds — near-miss learning** (`HandPinchClassifierTests`):

| Scenario | fixed thresholds | old adaptive | new adaptive |
|---|---:|---:|---:|
| wide-contact user (gap 0.32), 60 taps: recall | 0.183 | 0.317 | **0.933** (precision 1.000) |
| gaps 0.30/0.34/0.38 × 3 seeds × 40 taps (360 taps): recall | 0.250 | — | **0.947** (3 FP in non-pinch blocks) |
| normal user, adaptive on: recall / precision | 1.000 / 1.000 | — | 1.000 / 1.000 |

Repeated shallow "dips" (≥2, depth ≥ 0.5 of the way to the threshold, 50 ms–1 s) pull the on/off thresholds toward the
user's real contact distance. Still **off by default** (menu: *Adaptive pinch thresholds*).

**Pupil centre, synthetic eye patches** (`GazePupilLocatorTests`, error in eye-widths, mean / p95):

| Patch | landmark (σ 0.05, assumed) | dark centroid | Timm–Barth |
|---|---:|---:|---:|
| 48 px clean | 0.0631 / 0.1158 | 0.0157 / 0.0359 | **0.0082 / 0.0204** |
| 48 px + glint + lashes + noise | 0.0631 / 0.1158 | 0.0357 / 0.0637 | **0.0139 / 0.0281** |
| 32 px | 0.0609 / 0.1175 | 0.0452 / 0.0862 | **0.0219 / 0.0352** |

Runtime 17.85 ms/eye (52×30 patch, debug build). **Real-video caveat:** on a real clip with small eyes (median
19.5 px wide) Timm–Barth made jitter *worse* (0.0120 → 0.0456 eye-widths). It is therefore gated: eye ≥ 32 px,
distinctness ≥ 1.6, result inside the eye contour, shift ≤ 0.15 eye-width — otherwise the landmark pupil is kept.
On that clip the gated version is neutral (0.0120 → 0.0120; only 18 eyes qualified).

than the CV estimate. Original low-noise calibration test unchanged (11.36 / 23.78 pt).

**Appearance model (CoreML).** `scripts/convert_gaze_model.py` converts an L2CS-style model from
[yakhyo/gaze-estimation](https://github.com/yakhyo/gaze-estimation) (code MIT) to `GazeAppearance.mlpackage`
(fp16, mobileone_s0 by default; ~4 s conversion; torch [0.6157, 0.3643] vs CoreML [0.6152, 0.3623] rad).
**The weights are trained on Gaze360 (non-commercial research licence) and are not redistributed** — each user
converts them locally; the app works without them. On a real 329-frame clip: Vision face found 329/329,
Vision ≈ 11–12.7 ms/frame, CoreML 2.55 ms/frame; small faces → noisy (median frame-to-frame change 7.53°), which is
why calibration decides per user whether to use it.

**Webgrid simulator** — see the grid sweep above: gazeOnly 6×6 0.030 → 2.842 BPS, 10×10 0 → 1.033; gazeEKF 6×6
0.004 → 3.274, 10×10 0 → 3.077, 15×15 0 → 2.531; corrected presets at 30×30 essentially unchanged
(gazeHeadEKF 5.315 → 5.299, gazeHandEKF 5.331 → 5.356, gazeHeadHandEKF 5.151 → 5.078; all within one SD).
